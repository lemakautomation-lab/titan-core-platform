## Mission Exit Gate

all controls implemented or explicitly verified as already satisfied; targeted tests GREEN; relevant regression GREEN; build GREEN; security/tenant/RBAC implications verified; migration/API contract verified where applicable; documentation/evidence captured.

18. UNIVERSAL CONTROL GATES

Scope fidelity — implement only the authoritative mission/control boundary.

Inspection first — inspect current code, tests, schema, routes and composition before changing production code.

One-control discipline — implement one control/capability at a time and verify it before moving to the next.

Security — authentication, authorization, tenant isolation, input validation, data exposure, abuse controls, audit/security events, safe errors, logging, relevant OWASP threats, ISO-aligned controls and privilege-escalation risk are considered for every applicable feature.

Data integrity — constraints, foreign keys, uniqueness, referential integrity, transactions and concurrency are addressed where relevant.

Scalability — efficient queries/indexes, pagination, data minimisation, derived/aggregated metrics and separation of high-volume telemetry from transactional data are used where applicable.

Testing — targeted integration/security tests precede broader regression; only actual command output establishes GREEN.

Frontend truth — never claim a local UI change unless the mission explicitly requires one.

AI governance — authorised data only, explainability, human oversight, auditability, override and validated boundaries for AI features.

Commercial entitlement — paid access and user-type/plan entitlements are server-side controls wherever commercial access is implemented.

Evidence — record build, test, migration, verification and sign-off evidence for each completed control.
